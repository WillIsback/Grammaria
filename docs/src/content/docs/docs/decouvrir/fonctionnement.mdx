title: "Fonctionnement"
description: "Correction par le LLM, diff, croisement avec LanguageTool, fiches, journal et note."
---

Grammaria sépare deux tâches que les correcteurs à base de LLM mélangent d'habitude : **corriger** et **expliquer**.

## 1. Le LLM corrige, et rien d'autre

Le modèle reçoit votre texte et renvoie uniquement le texte corrigé. Il ne produit pas la liste de ses corrections : cette liste rallongeait la génération et son contenu variait d'une fois à l'autre.

Le texte s'affiche au fil de la génération. Le bouton **Copier** est utilisable dès les premiers mots.

## 2. Les modifications sont calculées, pas générées

Grammaria compare mot à mot le texte d'origine et le texte corrigé. Chaque différence devient une correction « avant → après ». Ce calcul est déterministe et ne coûte aucun appel au modèle.

## 3. Les règles de LanguageTool classent les fautes

Pendant que le LLM travaille, les règles françaises de [LanguageTool](https://languagetool.org), intégrées à Grammaria (dans le serveur, ou dans l'application de bureau elle-même), analysent le texte d'origine. Il fournit pour chaque détection un identifiant de règle stable, une catégorie et un message.

Une détection LanguageTool n'est retenue que si le LLM a **réellement modifié** le passage concerné. Ce croisement écarte les faux positifs de LanguageTool, par exemple un nom propre signalé à tort.

Une modification qui ne change que la terminaison d'un mot (« était → étaient », « aidés → aidé ») est classée comme **accord** et comptée, même si LanguageTool ne l'a pas signalée.

À l'inverse, une modification du LLM qu'aucune détection n'explique reste affichée, avec la mention « Non classé », et n'est pas comptée.

Une modification qui ne touche que la ponctuation ou les espaces (virgule ajoutée, point final, guillemets) est une **correction silencieuse** : elle est appliquée dans le texte corrigé, mais n'apparaît pas dans la liste, n'est pas comptée et n'est pas enregistrée dans le journal. L'apostrophe et le trait d'union n'en font pas partie : ils appartiennent aux mots (« l'équipe », « est-ce »).

## 4. Les confusions courantes ont leur fiche

Treize confusions sont reconnues directement dans le diff, sans dépendre de LanguageTool : a/à, ou/où, et/est, on/ont, son/sont, ces/ses, ce/se, c'est/s'est, la/là, sa/ça, peu/peut/peux, les terminaisons -er/-é/-ez, et le nom en -ail, -eil ou -euil confondu avec le verbe (travail/travaille, conseil/conseille).

Chacune est accompagnée d'une fiche au format « remplacez par X, car Y ». Voir [Corrections et fiches de règles](/docs/utiliser/corrections/).

## 5. Le journal garde la trace

Chaque faute retenue est enregistrée dans une base SQLite locale : la règle, le mot fautif, la correction et la phrase. C'est ce journal qui permet de repérer les fautes récurrentes (astuce, puis choix entre deux formes sur le bouton Copier) et d'afficher l'écran [Progression](/docs/utiliser/progression/) et les [badges](/docs/utiliser/badges/). Voir [Note et journal des fautes](/docs/utiliser/note-et-journal/).

## Schéma

```
Votre texte ──┬──► LLM ──────────► texte corrigé (affiché en direct)
              │                          │
              └──► LanguageTool ──┐      │
                                  ▼      ▼
                           diff + croisement
                                  │
                    ┌─────────────┼──────────────┐
                    ▼             ▼              ▼
               corrections      note        journal SQLite
               et fiches       sur 20
```

## Si le correcteur grammatical est indisponible

La correction fonctionne quand même. Seules les confusions des fiches et les accords sont alors classés, et le message « Le correcteur grammatical est indisponible : l'analyse des fautes est partielle. » s'affiche.
