## Mes textes sont-ils envoyés quelque part ?

Ils sont envoyés uniquement au modèle que vous avez configuré (`LLM_TARGET` sur un serveur, **Paramètres → IA** dans l'application de bureau) : l'analyse grammaticale tourne dans Grammaria même. Avec un modèle local, rien ne quitte votre réseau. Le journal ne conserve que les phrases contenant une faute.

## Le message « Le correcteur grammatical est indisponible » s'affiche

Le [moteur de grammaire](/docs/decouvrir/moteur/) intégré n'a pas pu analyser le texte. Consultez les journaux du serveur (lignes `[Grammar]`) et vérifiez que le binaire du moteur est présent (`moteur/grammaria`, construit par `npm run build:moteur` ; il est inclus dans l'image Docker). Si le moteur s'arrête ou ne répond plus, le serveur le relance à la correction suivante. Vous pouvez aussi l'interroger directement :

```bash
curl -s -X POST http://localhost:25000/api/check -H "Content-Type: application/json" -d '{"text":"Ils on vu le film."}'
```

Sans correcteur grammatical, la correction fonctionne mais seules les confusions des fiches et les accords sont classés.

Dans l'application de bureau, un bandeau signale un correcteur qui n'a pas pu se charger, et la cause est notée dans le [journal technique](/docs/demarrer/application-bureau/#journal-technique).

## Application de bureau : le premier contrôle de grammaire est lent

Depuis la version 0.4.0, le correcteur est prêt environ 1,5 seconde après le lancement (environ 6 secondes en version 0.3), et chaque contrôle prend quelques dizaines de millisecondes. Si le premier contrôle reste lent, consultez le [journal technique](/docs/demarrer/application-bureau/#journal-technique) (ligne « Moteur chargé en … ms »).

## Application de bureau : où trouver le journal technique ?

Dans `grammaria.log`, sous `%LOCALAPPDATA%\fr.willisback.grammaria\logs\` (Windows) ou `~/.local/share/fr.willisback.grammaria/logs/` (Linux). Il ne contient ni vos textes ni votre clé API : vous pouvez le joindre à une demande d'aide. Voir [Application de bureau](/docs/demarrer/application-bureau/#journal-technique).

## Application de bureau : mon mode de correction a changé après la mise à jour vers la 0.3

C'est attendu : le journal, les réglages du modèle, la clé API et les mots ajoutés au dictionnaire sont repris, mais pas les préférences de la barre latérale (mode et types de corrections). Choisissez-les à nouveau une fois.

## La correction échoue ou ne démarre pas

Vérifiez que le serveur du modèle répond :

```bash
curl -s http://localhost:25000/v1/models
```

Une erreur 502 signifie que Grammaria ne joint pas `LLM_TARGET`. Le message affiché sous le texte en donne la cause : serveur injoignable, requête refusée (clé d'API manquante ou invalide), ou aucun modèle détecté, auquel cas renseignez `LLM_MODEL_NAME`.

## Le modèle répond à mon texte au lieu de le corriger

Le prompt l'interdit, mais un petit modèle peut ne pas respecter la consigne. Essayez un modèle plus capable.

## Le modèle renvoie une réponse vide ou du texte de réflexion

Certains modèles produisent un bloc de réflexion avant leur réponse. Laissez `LLM_DISABLE_THINKING=true` pour vLLM et Qwen ; mettez `false` pour les fournisseurs qui rejettent ce paramètre.

## Pourquoi une correction est-elle « Non classé » ?

Le modèle a modifié un passage que ni les fiches, ni la détection des accords, ni le moteur de grammaire n'expliquent. C'est le plus souvent une reformulation de style. Elle n'entre pas dans la note.

## Ma note est très basse sur un message court

C'est attendu : une faute dans dix mots représente une densité élevée. Fiez-vous à la moyenne sur sept jours, qui pondère par le nombre de mots.

## Le journal a disparu après une mise à jour du conteneur

Le fichier SQLite doit être sur un volume. Voir [Déploiement Docker](/docs/exploiter/docker/).

## Peut-on avoir plusieurs utilisateurs ?

Non. Grammaria est conçu pour une personne et n'a pas d'authentification.
