## Vue d'ensemble

Les routes de l'interface (`/api/*`, `/v1/*`) sont traitées par un seul gestionnaire, `api/handler.ts`, partagé entre le serveur web et l'application de bureau. Seules ses dépendances changent : elles lui sont injectées (`api/deps.ts`).

```
                 Interface React : fetch("/api/…"), fetch("/v1/…")
                                  │
          ┌───────────────────────┴────────────────────────┐
   Version web (Bun)                              Application de bureau (Tauri)
   HTTP vers server.ts                            fetch intercepté dans la page
          │                                       (src/desktop/pont.ts)
          └──────────────► api/handler.ts ◄────────────────┘
                    (routes, analyse, relance du modèle)
                                  │
          ┌───────────────────────┴────────────────────────┐
   journal : bun:sqlite                           journal : SQLite par Rust (db.rs)
   (journal.driver.bun.ts)                        (src/desktop/journal.driver.tauri.ts)
   correcteur : processus grammaria (grammar.ts)  correcteur : moteur lié (correcteur.rs)
   réglages, mots : fichiers (settings.ts)        réglages, clé, mots : Rust (store.rs)
   modèle : SDK OpenAI                            modèle : relais Rust (llm.rs)
```

Le serveur Bun sert aussi les fichiers statiques de l'interface (`dist/`). L'application de bureau n'a pas de serveur : Tauri sert la page embarquée (`dist/bureau`). Voir [Application de bureau (build)](/docs/reference/bureau/).

## Fichiers

| Fichier | Rôle |
|---|---|
| `server.ts` | Serveur Bun : fichiers statiques et dépendances réelles du gestionnaire d'API (SQLite, fichiers, SDK OpenAI) |
| `api/handler.ts` | Gestionnaire des routes `/api/*` et `/v1/*`, partagé par le serveur et le bureau ; `api/deps.ts` décrit ses dépendances |
| `grammar.ts` | Correcteur grammatical du serveur : lance le moteur Rust `moteur/grammaria serve` une fois, lui confie les textes, le relance s'il s'arrête ou ne répond plus |
| `scripts/moteur/construire.sh` | Construit le moteur (`npm run build:moteur`) : récupère [grammaria-rc](https://github.com/WillIsback/grammaria-rc) à la révision épinglée dans `src-tauri/Cargo.toml`, le compile et copie ses données dans `moteur/` |
| `journal.ts` | Journal des fautes, indépendant du moteur SQLite |
| `journal.driver.ts` | Interface des pilotes du journal ; `journal.driver.bun.ts` (serveur, `bun:sqlite`) et `src/desktop/journal.driver.tauri.ts` (bureau, commandes Rust) |
| `journal.rules.ts` | État des règles et historique dans la base du journal ; migration du schéma |
| `journal.badges.ts` | Badges obtenus dans la base du journal ; attribution rétroactive à la migration |
| `config.ts` | Lecture des variables d'environnement |
| `telemetry.ts` | Initialisation d'OpenTelemetry |
| `src/analysis/diff.ts` | Diff au niveau du mot |
| `src/analysis/fiches.ts` | Fiches de règles et détection des confusions |
| `src/analysis/analyze.ts` | Croisement du diff et de LanguageTool |
| `src/analysis/score.ts` | Note sur 20 |
| `src/analysis/regles/seuils.ts` | Seuils du cycle de vie des règles |
| `src/analysis/regles/cycle.ts` | Cycle de vie d'une règle : transitions (fonction pure) |
| `src/analysis/regles/intervention.ts` | Choix de l'astuce ou des deux formes à afficher |
| `src/analysis/progression/reglages.ts` | Réglages de l'écran Progression (score de maîtrise, fenêtres, minimums) |
| `src/analysis/progression/calcul.ts` | Calcul de l'écran Progression à partir des lignes du journal (fonction pure, horloge injectée) |
| `src/components/progression/` | Écran Progression et ses graphiques SVG |
| `src/analysis/badges/catalogue.ts` | Catalogue des badges (données) |
| `src/analysis/badges/evaluation.ts` | Évaluation des badges à partir des faits du journal (fonction pure) |
| `src/components/BadgeGallery.tsx`, `BadgeNotice.tsx` | Galerie des badges (en bas de l'écran Progression) et notification d'un badge obtenu |
| `src/hooks/useCorrector.ts` | Orchestration côté interface |
| `src/utils/prompt.ts` | Construction du prompt |
| `src/desktop/` | Application de bureau, côté page : amorce, pont `fetch`, dépendances par les commandes Rust (dont le correcteur), journal technique, autotest |
| `src-tauri/` | Application de bureau, côté Rust : commandes (SQLite, réglages, relais du modèle, correcteur grammatical, mise à jour, journal technique `grammaria.log`) |
| `vite.config.ts` | Toute la configuration de l'outillage |

## Choix de conception

- **Le code d'analyse est partagé.** `src/analysis` et `api/handler.ts` ne dépendent ni de Bun ni de Node ; ils sont exécutés par le serveur web, par la page de l'application de bureau, et testés sous Vitest.
- **L'analyse ne bloque jamais la correction.** Si le correcteur grammatical ou le journal échoue, le texte corrigé reste affiché et copiable.
- **Une clé stable par règle.** Les confusions des fiches ont une clé interne (`PAIRE:on/ont`) ; les autres fautes utilisent l'identifiant de règle de LanguageTool. C'est ce qui permet de compter les récurrences.
- **Un correcteur grammatical intégré.** Depuis la version 0.4.0, c'est [grammaria-rc](https://github.com/WillIsback/grammaria-rc), un moteur écrit en Rust : il exécute la chaîne française de LanguageTool (découpage, dictionnaire, désambiguïsation, règles XML et règles écrites en Java, orthographe) en lisant tels quels ses fichiers de règles et ses dictionnaires, plus environ 1 300 règles propres dont l'identifiant commence par `GRM_`. Le serveur le lance dans un processus à part (`grammaria serve`, relancé s'il s'arrête, tué s'il ne répond plus en 15 secondes, jamais laissé orphelin) ; l'application de bureau le lie à son backend Rust (`src-tauri/src/correcteur.rs`). Les deux utilisent la même révision, épinglée à un seul endroit (`src-tauri/Cargo.toml`), et un corpus de référence garantit des détections identiques. Il remplace le portage JavaScript de LanguageTool des versions 0.2 et 0.3 : chargement en moins d'une seconde au lieu de 4 à 5, environ 300 Mo de mémoire pour le serveur au lieu de 1 Go (mesures dans `benchmark/moteur-rust/rapport.md`).
