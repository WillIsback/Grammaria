Le projet utilise [Vite+](https://viteplus.dev) (`vp`), qui regroupe Vite, Vitest, Oxlint et Oxfmt. Toute la configuration est dans `vite.config.ts` : build, serveur de développement, tests, lint, format, Tailwind et hook de pre-commit.

Node.js `^22.18`, `^24.11` ou `>=26` est requis, ainsi que [Rust](https://rustup.rs) (1.75 au moins) et `git` pour construire le moteur grammatical.

## Commandes

| Commande | Rôle |
|---|---|
| `npm run dev` | Serveur de développement sur le port 25001 |
| `npm run build` | Vérification des types, puis build |
| `npm run check` | Format, lint et types |
| `npx vp check --fix` | Corrige le format et les règles de lint réparables |
| `npm run test:run` | Tests Vitest |
| `npm run test:coverage` | Tests avec couverture |
| `npm run test:journal` | Tests du journal et du correcteur grammatical, exécutés par Bun |
| `npm run build:moteur` | Construit le moteur grammatical (`moteur/grammaria` et ses données `moteur/data/`) : récupère grammaria-rc à la révision épinglée dans `src-tauri/Cargo.toml` (seule source de vérité), le compile dans `.moteur-build/`. `GRAMMARIA_RC_SRC` désigne un clone local à utiliser à la place du réseau (il doit être à la même révision ; `GRAMMARIA_RC_REV_LIBRE=1` pour travailler sur le moteur lui-même). À lancer avant `npm run test:journal`, `bun run server.ts` et le build du bureau |
| `npm run build:bureau` | Build de l'application de bureau, côté page : interface (`dist/bureau`). Sans Bun |
| `npm run reference:correcteur` | Régénère la référence du correcteur (`tests/fixtures/correcteur/reference.json`) avec le correcteur du serveur. Nécessite Bun |

## Lancer en développement

Dans un premier terminal, le serveur Bun (API et relais) :

```bash
bun run server.ts
```

Dans un second, l'interface avec rechargement à chaud :

```bash
npm run dev
```

Le serveur de développement relaie `/api` et `/v1` vers le port 25000.

## Application de bureau

L'application de bureau n'utilise pas le serveur Bun : la page embarquée traite elle-même les routes avec `api/handler.ts`, et Rust fournit SQLite, les réglages et le relais du modèle. Pour la construire et la vérifier (tests Rust, autotest dans la vraie WebView), voir [Application de bureau (build)](/docs/reference/bureau/#construire-en-local).

```bash
npx tauri build --debug
```

```bash
cd src-tauri && cargo test
```

## Tests

- Les tests importent depuis `vite-plus/test`.
- Le pilote du journal du serveur utilise `bun:sqlite`, indisponible sous Vitest : ses tests sont dans `tests-bun/` et tournent avec `bun test`. Sous Vitest, le journal est testé avec le SQLite de Node, par le pilote du bureau et des commandes Rust simulées.
- `server.ts` ne peut pas être importé sous Vitest ; plusieurs tests vérifient son code source directement.

## Hook de pre-commit

`vp check --fix` s'exécute sur les fichiers indexés à chaque commit. La variable `VP_GIT_HOOKS=0` désactive l'installation du hook.
