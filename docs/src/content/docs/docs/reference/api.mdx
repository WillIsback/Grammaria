Toutes les routes sont servies par le serveur Bun, sur le port `PORT`.

## Correction

### `POST /v1/chat/completions`

Corps au format OpenAI (`model`, `messages`, `temperature`), plus un champ `correction_mode` utilisé pour la télémétrie. La réponse est un flux SSE :

```
data: {"delta":"Bonjour "}
data: {"delta":"à tous."}
data: {"done":true,"text":"Bonjour à tous.","duration":412}
```

En cas d'erreur pendant le flux : `data: {"error":"…"}`. Des lignes `: keepalive` sont émises toutes les cinq secondes.

### `/v1/*`

Les autres routes, dont `GET /v1/models`, sont relayées telles quelles au serveur du modèle.

### `POST /api/check`

Analyse le texte avec le correcteur grammatical intégré (règles françaises de LanguageTool). L'interface l'appelle en parallèle de la correction par le modèle.

```json
{ "text": "Les enfants était content." }
```

`text` est obligatoire, non vide, et limité à 20 000 caractères. Réponse (extrait) :

```json
{
  "matches": [
    {
      "offset": 12,
      "length": 5,
      "message": "Le verbe devrait être à la 3ᵉ personne du pluriel.",
      "shortMessage": "",
      "replacements": [{ "value": "étaient" }],
      "rule": {
        "id": "ACCORD_SUJET_VERBE",
        "issueType": "uncategorized",
        "category": { "id": "CAT_GRAMMAIRE", "name": "Grammaire" }
      }
    }
  ]
}
```

Les détections suivent le format de LanguageTool. Erreurs : 400 si le JSON ou le corps est invalide, 405 pour une autre méthode que `POST`, 503 si le correcteur échoue.

## Analyse et journal

### `POST /api/analyze`

Calcule le diff, le croise avec les détections, enregistre le résultat dans le journal, met à jour l'état des règles et renvoie le tout, avec ce qu'il faut afficher près du bouton Copier.

```json
{
  "original": "Ils on vu le film.",
  "corrected": "Ils ont vu le film.",
  "matches": []
}
```

`matches` est le tableau renvoyé par `POST /api/check`. Chaque faute indique sa `source` : `fiche`, `lt` (LanguageTool) ou `accord` (déduit du diff). `original` et `corrected` sont limités à 20 000 caractères.

Réponse :

```json
{
  "corrections": [
    {
      "start": 4,
      "end": 6,
      "avant": "on",
      "apres": "ont",
      "faults": [{ "ruleKey": "PAIRE:on/ont", "source": "fiche", "counted": true }],
      "fiche": { "titre": "on / ont", "astuce": "Remplacez par « avaient »…" }
    }
  ],
  "wordCount": 5,
  "faultCount": 1,
  "unclassifiedCount": 0,
  "score": 0,
  "week": { "texts": 12, "words": 840, "faults": 9, "score": 17.9 },
  "intervention": null,
  "reussites": []
}
```

`start` et `end` situent le passage dans le texte d'origine (fin exclue).

`intervention` vaut `null`, ou l'une des deux formes suivantes. Le serveur en choisit au plus une par texte et la compte dans le budget de la règle (une par règle et par jour).

```json
{
  "type": "astuce",
  "ruleKey": "PAIRE:on/ont",
  "titre": "on / ont",
  "texte": "Remplacez par « avaient »…"
}
```

```json
{
  "type": "choix",
  "choiceId": 57,
  "ruleKey": "PAIRE:on/ont",
  "titre": "on / ont",
  "explication": "Remplacez par « avaient »…",
  "avant": "Ils ",
  "apres": " vu le film.",
  "formes": [
    { "texte": "on", "correcte": false },
    { "texte": "ont", "correcte": true }
  ]
}
```

`choiceId` identifie ce choix précis (c'est l'`id` de l'événement `choix` dans l'historique) : il est à renvoyer à `POST /api/rules/answer`. `avant` et `apres` sont l'extrait de la phrase de part et d'autre de la forme. `formes` est déjà dans l'ordre d'affichage, tiré au hasard par le serveur.

`reussites` liste les règles devenues « acquises » avec ce texte : `[{ "ruleKey": "PAIRE:on/ont", "titre": "on / ont" }]`.

## Cycle de vie des règles

L'état des règles est mis à jour à chaque `POST /api/analyze`. Les seuils sont définis dans `src/analysis/regles/seuils.ts`, la logique de transition dans `src/analysis/regles/cycle.ts`. Les dates sont en millisecondes depuis 1970.

### `GET /api/rules`

Toutes les règles suivies, de la plus récemment fautive à la plus ancienne.

```json
{
  "rules": [
    {
      "ruleKey": "PAIRE:on/ont",
      "label": "on / ont",
      "categoryName": "Confusion de mots",
      "fiche": { "titre": "on / ont", "astuce": "Remplacez par « avaient »…" },
      "state": "travaillee",
      "stateSince": 1795000000000,
      "occurrences": 9,
      "firstFaultAt": 1794000000000,
      "lastFaultAt": 1795000000000,
      "tipsShown": 3,
      "choicesShown": 2,
      "choicesCorrect": 1,
      "choicesWrong": 1,
      "lastSolicitedAt": 1795000000000,
      "solicitationsThatDay": 1,
      "acquiredAt": null,
      "relapses": 0
    }
  ],
  "counts": { "observee": 4, "signalee": 1, "travaillee": 1, "acquise": 0 },
  "thresholds": { "signalementOccurrences": 3, "signalementFenetreJours": 7, "…": "…" }
}
```

| Champ | Sens |
|---|---|
| `state` | `observee`, `signalee`, `travaillee` ou `acquise` |
| `stateSince` | date d'entrée dans l'état courant |
| `label`, `fiche` | nom lisible de la règle ; `fiche` vaut `null` pour une règle sans fiche |
| `occurrences` | nombre total de fautes sur la règle |
| `tipsShown` | astuces affichées depuis la dernière entrée en « signalée » |
| `choicesShown`, `choicesCorrect`, `choicesWrong` | choix à deux formes proposés, bonnes et mauvaises réponses |
| `acquiredAt` | date d'acquisition ; `null` si la règle n'est pas acquise |
| `relapses` | nombre de rechutes (faute après acquisition) |
| `thresholds` | les seuils en vigueur |

### `GET /api/rules/events?limit=200&ruleKey=…`

Historique daté, du plus récent au plus ancien. `limit` va de 1 à 1000 (200 par défaut) ; `ruleKey` restreint à une règle.

```json
{
  "events": [
    { "id": 12, "ruleKey": "PAIRE:on/ont", "at": 1796300000000, "type": "rechute", "from": "acquise", "to": "signalee" },
    { "id": 11, "ruleKey": "PAIRE:on/ont", "at": 1796200000000, "type": "acquise", "from": "travaillee", "to": "acquise" },
    { "id": 10, "ruleKey": "PAIRE:on/ont", "at": 1795000000000, "type": "reponse_juste", "from": null, "to": null }
  ]
}
```

`type` vaut `observee`, `signalee`, `travaillee`, `acquise` ou `rechute` pour un changement d'état (`from` et `to` sont alors renseignés ; `from` est `null` à la première faute), et `astuce`, `choix`, `reponse_juste` ou `reponse_fausse` pour une sollicitation.

### `POST /api/rules/answer`

Enregistre la forme cliquée lors d'un choix à deux formes. `choiceId` est celui reçu dans l'intervention. L'interface appelle cette route après avoir copié le texte ; un échec n'empêche pas la copie.

```json
{ "choiceId": 57, "correct": true }
```

Réponse : `{"recorded": true}`. Chaque choix ne reçoit qu'une réponse.

| Code | Cas |
|---|---|
| 400 | corps invalide (`choiceId` entier, `correct` booléen) |
| 404 | aucun choix ne porte cet identifiant |
| 409 | le choix a déjà reçu sa réponse, ou un choix plus récent l'a remplacé pour la même règle |

### `GET /api/journal?days=7`

Bilan de la période (entier de 1 à 365 jours ; 7 si `days` est absent ou illisible, 1 pour une valeur inférieure à 1) : `period` (textes, mots, fautes, note), `unclassified`, et les vingt règles (`rules`) et mots (`words`) les plus fréquents.

### `GET /api/progress`

Tout l'écran **Progression** en une seule requête, calculé depuis le journal par `src/analysis/progression/calcul.ts` (réglages dans `reglages.ts`). Les semaines vont du lundi 0 h au lundi suivant, heure locale du serveur ; la dernière est la semaine en cours. L'état des règles est celui qui est enregistré : « acquise » n'est réévalué qu'à un `POST /api/analyze`. Mêmes contrôles que les autres routes du journal (en-tête `Host` et origine en mode bureau, CORS) ; 405 pour une autre méthode que `GET` ou `OPTIONS`.

Réponse (extrait, deux semaines sur douze) :

```json
{
  "generatedAt": 1795115893520,
  "empty": false,
  "weeks": 12,
  "since": 1788134400000,
  "mastery": {
    "score": 68,
    "level": "En bonne voie",
    "quality": 81,
    "rulesShare": 50,
    "acquired": 2,
    "inCycle": 4,
    "recent": { "texts": 24, "words": 1343 },
    "minimum": { "texts": 5, "words": 300 },
    "weights": { "quality": 0.6, "rules": 0.4 },
    "recentWeeks": 4
  },
  "totals": { "texts": 65, "words": 3884, "faults": 98, "score": 15, "faultsPer100": 2.52 },
  "period": { "texts": 65, "words": 3884, "faults": 98, "score": 15, "faultsPer100": 2.52 },
  "recent": { "texts": 24, "words": 1343, "faults": 26, "score": 16.1, "faultsPer100": 1.94 },
  "previous": { "texts": 26, "words": 1547, "faults": 39, "score": 15, "faultsPer100": 2.52 },
  "trend": "baisse",
  "series": [
    { "start": 1788134400000, "end": 1788739200000, "texts": 0, "words": 0, "faults": 0, "score": null, "faultsPer100": null },
    { "start": 1788739200000, "end": 1789344000000, "texts": 3, "words": 252, "faults": 5, "score": 16, "faultsPer100": 1.98 }
  ],
  "rules": {
    "counts": { "observee": 2, "signalee": 0, "travaillee": 2, "acquise": 2 },
    "active": [
      { "ruleKey": "PAIRE:et/est", "label": "et / est", "categoryName": "Confusion de mots", "state": "travaillee", "stateSince": 1794900000000, "occurrences": 15, "lastFaultAt": 1795000000000, "acquiredAt": null }
    ],
    "acquired": [
      { "ruleKey": "PAIRE:on/ont", "label": "on / ont", "categoryName": "Confusion de mots", "state": "acquise", "stateSince": 1792600000000, "occurrences": 11, "lastFaultAt": 1791300000000, "acquiredAt": 1792600000000 }
    ]
  },
  "frequentRules": [
    { "ruleKey": "PAIRE:a/à", "label": "a / à", "categoryName": "Confusion de mots", "count": 17, "state": "travaillee" }
  ],
  "trapWords": [{ "word": "apareil", "replacement": "appareil", "count": 14 }]

```

| Champ | Sens |
|---|---|
| `empty` | `true` quand le journal ne contient aucun texte |
| `since` | début de la première des `weeks` semaines affichées |
| `mastery.score` | score de maîtrise de 0 à 100 ; `null` tant que la fenêtre récente compte moins de `minimum.texts` textes ou `minimum.words` mots |
| `mastery.quality` | note moyenne des `recentWeeks` dernières semaines, ramenée sur 100 |
| `mastery.rulesShare` | part (sur 100) des règles acquises parmi les règles entrées dans le cycle (`inCycle` : signalées, travaillées, acquises) ; `null` s'il n'y en a aucune, le score vaut alors la qualité seule |
| `totals`, `period`, `recent`, `previous` | depuis le premier texte, sur les semaines affichées, sur les `recentWeeks` dernières semaines, et sur les semaines d'avant de même durée |
| `faultsPer100`, `score` | fautes pour 100 mots et note sur 20 ; `null` sans aucun mot |
| `trend` | `baisse`, `hausse` ou `stable` pour les fautes pour 100 mots (`recent` contre `previous`) ; `null` si l'une des périodes n'a aucun mot |
| `series` | une entrée par semaine, de la plus ancienne à la plus récente |
| `rules.active`, `rules.acquired` | règles signalées ou travaillées (les plus récemment fautives d'abord), et règles acquises (les plus récemment acquises d'abord) |
| `frequentRules` | les huit règles les plus fréquentes sur les semaines affichées, hors `FR_SPELLING_RULE` ; `state` vaut `null` pour une règle hors cycle |
| `trapWords` | les dix mots le plus souvent mal orthographiés (`FR_SPELLING_RULE`) sur les semaines affichées, en minuscules, avec la correction la plus fréquente |

Score : `arrondi(100 × (0,6 × qualité + 0,4 × part des règles acquises))`, qualité et part étant comprises entre 0 et 1 avant arrondi (qualité = note récente / 20). Sans règle entrée dans le cycle : `arrondi(100 × qualité)`. Explication en langage simple dans [Progression](/docs/utiliser/progression/).

### `DELETE /api/journal`

Efface tout le journal et remet à zéro l'état des règles et leur historique. Réponse : `{"purged": true}`.

## Mots valides

`GET` et `POST /api/valid-words` lisent et complètent `public/data/valid-words.json`. Ces routes sont héritées d'ai_corrector ; l'interface actuelle ne les utilise pas.
